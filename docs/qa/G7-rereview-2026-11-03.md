## 3. SQL review notes (`2026110301*`–`2026110304*`)

- **PL/pgSQL correctness: OK.**
  - `old`/`new` access in INSERT/DELETE triggers is safe on PG ≥ 11. `coalesce(new, old)` returns the right row for BEFORE INSERT, UPDATE and DELETE.
  - BEFORE triggers on `day_plans` fire in name order: `set_updated_at` → `stamp_wake_planned` → `wake_guard_before`.
  - SET LOCAL from `set_config(...,true)` inside a function with a `SET search_path` clause survives function exit, because it is a different GUC. `nullif(…,'')` handles the empty placeholder value left after the transaction.
  - The STABLE `_target_wake` is called from VOLATILE callers, so BEFORE triggers see the old state and AFTER triggers see the new state.
  - The `exception when others` around the planned-wake cast is fine.
  - `patch_day_plan`: no mass assignment, ownership of `template_id` checked, merges per block under the row lock.
- **search_path, security definer and grants: OK.** Every object is schema-qualified. Helpers are revoked from public, anon and authenticated. Public RPCs are revoked from anon and granted to authenticated. Clients can't write `wake_snapshots`.
- **Normal flows blocked?**
  - Sign-up seeding, onboarding upserts, Plan saves and Today saves don't error. They can create harmless snapshots.
  - They can, however, **freeze legitimate changes** (R2-4 b): non-atomic two-step writes look like "target → NULL".
  - **User deletion is blocked** (R2-10).
  - An invalid `profiles.timezone` (R-M1-5, API only) now makes *every* day-plan and template write fail. It used to break only `press_wake` and block logs.
- **Anti-cheat bypasses:** R2-1 (UI), R2-2 (API), R2-3 (design), R2-7 (API race), R2-8 (UI).
- **Client never decides rewards:**
  - Ticket and coin grants are server-side.
  - The Sunrise target still partly comes from client data (`planned.wake`, bounded and pre-committed), and the window and timezone are client-writable through the table API (R2-2).
- **Migration transition:** existing `day_plans` rows get `wake_planned_at = NULL`, so pushes saved before deploy aren't honored until re-saved (S4).

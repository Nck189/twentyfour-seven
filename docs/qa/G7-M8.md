# G7 independent review — M8 (exercise + animals)

**Commit range:** `9b3b767..469d8b4` (branch `m8-local`, 7 commits, 34 files, +2838/−12). Repo left clean (`git status` empty).

## Verdict: FAIL

1 open S1 and 1 open S2.

**Summary.** The server design holds up well. Workouts can only be logged through `log_exercise`. `exercise_logs`, `animals`, `inventory` and `game_state` refuse direct writes. The internal helpers can't be called. Pet, collect and feed only work on your own animals. Idempotency keys are scoped to each user, and concurrent calls are serialised on the `game_state` row lock. The setup reward pays once, and the M7 setup steps still pay after the redefinition. The hatch roll matches the content over 200k rolls.

There is one hole: the "2 counted workouts per local day" cap (and the "3 pets per day" cap) is computed in `profiles.timezone`, which clients can change at will and which accepts arbitrary POSIX offsets. Scripting a timezone change before every pair of calls gives unlimited counted workouts, which means unlimited hatches, feed and love. Separately, the CJ-13 E2E main test can't pass: a `getByText` locator matches two elements, which is a strict-mode violation. UX, i18n and art are otherwise in good shape. The findings below them are S3/S4.

## What I verified and how

- **Scratch Postgres 16:** all 17 migrations apply cleanly. As `authenticated`, direct `insert/update/delete` on `exercise_logs` is refused (permission denied). `insert` on `animals`/`inventory` is refused (RLS), and `update animals`/`game_state` affects 0 rows. `_hatch_roll`, `_add_feed`, `_animal_produce`, `_grant_unlock` and `_setup_done` are refused (permission denied). Forging `exercise_logged` or `animal_petted` events is refused by RLS. `anon` can't execute `log_exercise` or `pet_animal`.
- **log_exercise:** a repeated key returns `repeat:true` with the same id. Under 10 min is not counted. A 3rd same-day workout is not counted. The egg goes 0→1→2→hatch. A new animal is fed 2 days. Six parallel calls with 2 shared keys gave 2 rows (no duplicates). Six parallel distinct keys at the cap gave 0 extra counted. Then the timezone exploit (R-M8-1).
- **Pet / collect / feed:** user B on user A's animal gets `not your animal` for all three. 3 pets count, the 4th returns `counted:false`. Collect before 24 h is refused. `use_feed` with no bag is refused.
- **Setup rewards:** after the M8 redefinition, `sleep_times`, `language`, `home_screen` and `exercise` all paid once. A repeat claim and a later goal change paid nothing more (feed stayed 3).
- **Hatch roll:** 200k SQL rolls gave common 50.1 / uncommon 29.9 / rare 13.0 / epic 5.0 / legendary 2.0 %, species even within each rarity. Edge inputs behaved as expected. The TS `hatchRoll` uses the same order (legendary first); the parity unit test passes.
- **Before `db push` on prod:** `useAnimals` selects `exercise_logs.counted`, which errors, so `status='error'` and ExerciseCard and AnimalPen render nothing (no crash). `egg_progress` falls back to 0. ExerciseSettings, WorkoutSlot and the setup card work. The Spark mutation reads `exercise_logs.at` only.
- **Checks:** `npx vitest run tests/unit`: 29 files / 231 tests pass. `tsc --noEmit` shows only the existing Next `LayoutProps` typegen errors (not M8). eslint on the changed M8 files is clean. `npx playwright test --list tests/e2e/animals.spec.ts` lists 18 tests (3 × 6 projects). E2E and integration tests could not run (no Supabase stack); I reviewed them by reading against the components and messages.
- **i18n:** EN/TH key sets are identical. All new user-facing strings go through i18n. No emoji.
- **UI and art:** touch targets use `min-h-11`/`h-11 w-11`/`tap`. Every sound goes through `play()`, which checks `soundOn`. The idle bob and blink are CSS and stopped by the global reduced-motion rule. The heart pop is skipped with reduced motion or skip-animations. Art reviewed from the components and screenshots (`art3/*.png`, `m8/*.png`).
- **Speculation, not verified:** whether axe flags the nested `aria-modal` dialogs (R-M8-8); whether PostgREST finishes an RPC whose client navigated away (R-M8-3).

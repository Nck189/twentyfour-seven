# G7 independent review — M7 (economy + gacha + setup rewards)

**Range:** `52faa3a..1f39f30` on `m7-local` (7 commits: 422b34e, 7f076e2, e317a01, c84901e, e10667a, 4aeef86, 1f39f30)
**Reviewer:** fresh G7 subagent, read-only (`git status` clean before and after)

## Verdict: FAIL (0 × S1, 2 × S2, 5 × S3, 7 × S4)

**Summary.** The server side holds up. I tried the attacks on a scratch Postgres 16 with every migration applied, and all of them were refused:
- pulling with no tickets, or as anon
- reusing another user's key
- racing the same key, and racing two keys for one ticket
- writing directly to `game_state` / `inventory` / `seed_dex` / `gacha_pulls` / `unlock_grants` / `decor` / events
- calling `_gacha_roll`, `_grant_unlock`, `_setup_done` or `_gacha_simulate` as authenticated
- planting a seed you don't own
- getting a setup reward twice

Other server checks:
- **Parity.** The SQL roll matches `lib/game/gacha.roll` on 20,000 random inputs.
- **100k SQL simulation.** It reproduces the rates in DECISIONS (55.4 / 26.2 / 12.5 / 4.1 / 1.8 %). Pity is never exceeded.
- **Rewards.** Shards, star-up costs and setup rewards all match `content/`.

**Why FAIL.** Both blockers are client/QA issues:
1. The reveal's **Skip** does not skip when tapped during the shake. The animation jumps back to the crack.
2. The mandatory critical journey **CJ-12** (gacha ×1/×10) has no E2E test.

There are also some S3 polish and robustness gaps.

The DECISIONS reasoning for moving the Perfect day, streak and Weekly review grants to M9/M10 is sound. Those grants depend on minimum-day, OEE and freeze rules, and on the hardening of client-written block logs, none of which exist yet. The "soft pity from the 61st" reading of SPEC "from 60" is also consistent and logged.

## What I verified and how

- **Unit tests.** `npx vitest run tests/unit`: 22 files, 210 tests passed. The M7 files (`gacha`, `gacha-sql`, `unlocks-sql`) have 12 tests, all passing.
- **Static checks.** `npx tsx scripts/qc-art-lint.ts` → "art lint OK — 11 art files". `npx tsx scripts/i18n-check.ts` → "514 keys in en/th". `npx eslint --max-warnings 0` on the M7 dirs → clean. The EN/TH key diff for `gacha.*`, `setup.*` and the new `farm.*` / `more.*` keys shows no missing keys. `tsc --noEmit` only fails on `LayoutProps`, which needs `next typegen` and is unrelated to M7.
- **Scratch PG16** (port 55447, the recipe's roles, all 17 migrations applied cleanly):
  - **Privileges.**
    - `_gacha_roll`, `_dupe_shards`, `_gacha_simulate`, `_setup_reward`, `_grant_unlock` and `_setup_done` are not executable by anon or authenticated.
    - `pull_gacha`, `star_up`, `plant_seed`, `claim_setup_rewards` and `report_home_screen` are executable by authenticated only.
    - The `*_grant*` RPCs are security definer and check `auth.uid()`.
  - **Direct writes as authenticated.** Each of these was refused with an RLS or permission error:
    - `update game_state set tickets = 999` affected 0 rows.
    - Inserts into `inventory`, `seed_dex`, `gacha_pulls`, `unlock_grants` and `decor`.
    - Events of type `unlock_granted` and `gacha_pull`.
  - **`pull_gacha` refusals.** `p_n = 3` → 22023; a short key → 22023; no tickets → P0001; anon → permission denied; user B with A's key → "not enough tickets", with no access to A's rows.
  - **`pull_gacha` ×10 with 12 tickets.**
    - Tickets went 12 → 2.
    - Pity ended at `{rare 5, epic 10, leg 10}`, which matches the sequence where the last rare was pull #5.
    - Duplicates gave 1 shard each for commons.
    - 10 seeds landed in the inventory and the Seed-dex counts sum to 10.
  - **`pull_gacha` repeat behaviour.** Repeating the same key returned the same results, charged nothing, and stayed a repeat even when called with a different `n`. Two sessions with the same key, the first held open with `pg_sleep(3)`: the second returned `repeat: true`, the user was charged 1 ticket, and there was 1 `gacha_pulls` row.
  - **`star_up`.** Refused when not in the dex or short of shards. With 200 shards it went ★2/★3/★4/★5 at costs 5/10/20/40 (125 left), then refused "already ★5".
  - **`plant_seed`.** An owned pumpkin planted and its inventory went 1 → 0. A 2nd pumpkin and an unowned `moon_melon` → 42501. An unknown crop or slot → 22023. A starter planted for free and carried its ★5.
  - **Parity, SQL vs TS.** 20,295 cases generated with `tsx` against the repo's `roll` were loaded with `\copy`. All 20,000 random cases matched on rarity, crop and pity. 5 exact-boundary cases differed (R-M7-8).
  - **`_gacha_simulate(100000)`** returned common 55,365, uncommon 26,208, rare 12,512, epic 4,102 and legendary 1,813, with max since-rare 9, since-epic 29 and since-legendary 72.
  - **Setup rewards.**
    - A fresh user gets `done: []`.
    - Onboarding *skipped*, first-10 `""` and a backlog estimate of 0 grant nothing.
    - A day-plan override checklist grants `checklist` (+20 coins).
    - `report_home_screen` grants true, then false; one flowers decor is created.
    - The ledger is select-only.
    - Amounts match `content/unlocks.ts`.
- **Code reading:** `CapsuleSheet` (reveal phases, timers, retry), `SeedDexSheet` (silhouette: CSS-flattened grey, never black; 44 px tiles; completion %), `PlotSheet` (owned seeds first, `aria-label` with qty), `SetupCard`/`useSetupRewards`, `MoreScreen`, `sfx.jingle` (3 + rank notes starting higher by rank, so pitch rises with rarity; mute respected), `Capsule.tsx` (tokens only, no outlines or gradients).
